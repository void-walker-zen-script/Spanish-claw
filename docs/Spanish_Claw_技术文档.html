项目概述

Spanish Claw 是一个面向西班牙语学习者的 Flask Web MVP，首版目标是验证「边听边点边查边收藏」的核心学习闭环： 用户在真实语境（情境对话、新闻）中听西语材料 → 点选单词/句子高亮 → 即时查看 AI 或本地词条解释（Ask Claw）→ 用浏览器本地存储收藏词句并在收藏页复盘。产品以一只名为「零灵灵」的吉祥物（2D 动画猫）作为首页引导与品牌载体。

产品同时具备明确的可扩展架构：后端通过统一抽象层接入多家大模型（OpenAI / Anthropic Claude / DeepSeek / Gemini / 本地术语表）， 并在无 Key 或模型不可用时自动降级到本地术语表，保证核心学习路径在任何情况下都可用。新闻模块通过 Google News RSS 直接拉取西语资讯，无第三方 SDK 依赖。

本项目的产品价值主张（PM 视角）：把「零散的西语输入」组织成「可点击、可解释、可收藏、可复盘」的闭环， 用 AI 降低查词/理解门槛，用情境与新闻提升学习动机——本质是一个以学习闭环为中心而不是以「词典/课程」为中心的产品。

一、用户需求分析

作为 PM，需求分析的第一步是把「用户是谁、痛什么、要什么」结构化，再转化为可排期的功能需求。本章是整篇文档的重点之一。

1.1 目标用户画像

  • 核心用户：有英语基础、以中文为母语的西语初学者（A1–A2）。他们具备迁移英语语法的能力，但缺乏沉浸语境与即时的、讲人话的解释。
  • 典型场景：碎片化时间（通勤、午休）想「真听懂一句西语」；读到西语新闻/社媒想快速理解；背单词但记不住用法。
  • 能力特征：需要「英文做桥接」的解释方式（借助英语理解西语结构），而非纯中文直译；需要例句保留西语原文以建立语感。

1.2 用户痛点（Jobs-to-be-Done）

  • 查词体验断裂：遇到不懂的词要跳出当前内容去词典 App，上下文丢失，回来就忘了。
  • 解释太「教科书」：通用翻译工具给的是词典义，不结合当前句子，初学者看不懂语法位置。
  • 动机难以持续：孤立背单词枯燥，缺乏「我在真实使用西语」的获得感。
  • 内容不敢碰：西语新闻/真实语料门槛高，没有辅助就放弃。

1.3 核心需求拆解

将用户痛点映射为产品需求，分为功能需求（FR）与非功能需求（NFR）：

编号需求类型用户需求产品功能响应
FR-1功能在语境中即时理解词句Lesson 页点击单词/句子高亮，弹出 Ask Claw 解释（AI 或本地术语表）
FR-2功能收藏并复盘学到的内容localStorage 收藏词句；Saved 页查看 / 筛选 / 删除
FR-3功能有真实可学的内容来源情境模块（咖啡馆/餐厅/图书馆）+ 语法 + News（西语 RSS）
FR-4功能获得陪伴感与动机吉祥物「零灵灵」首页动画引导 + Buddy（我的旅伴）模块
FR-5功能随时追问Ask Claw 对话式问答（带页面上下文的 /api/ask-claw）
NFR-1非功能没网/没 Key 也能学LLM Provider 自动降级到本地术语表（Local Glossary）
NFR-2非功能解释要「像学习助手」System Prompt 约束：中文解释、英文桥接、不编造、不复制外部源
NFR-3非功能低延迟、可离线收藏前端纯静态 + 本地存储；新闻 15 分钟缓存

1.4 需求优先级（MoSCoW）

MustFR-1 点击查词 · FR-2 收藏复盘 · NFR-1 降级保障 ShouldFR-3 情境/语法/News · FR-5 Ask Claw 追问 CouldFR-4 吉祥物引导 / Buddy 陪伴 · 发音模块 Won't(本版)多人对练 · 付费订阅 · 自适应难度引擎

PM 取舍逻辑：本版 MVP 只验证「闭环」本身（听→点→查→藏）是否成立，因此把资源压在 FR-1/FR-2 与降级保障（NFR-1）上； 吉祥物与 Buddy 是留存与动机层，放在 Could，但首页动画被保留为品牌与首次体验的「钩子」。

2.2 核心学习闭环（产品主线）

听 打开 Lesson → 播放西语音频/阅读材料 → 点 点击生词 / 句子 → 高亮选中 → 查 调 /api/ask-claw（带页面上下文）→ 返回中文+英文桥接的解释 → 藏 一键收藏到 localStorage → 复盘 在 Saved 页筛选 / 删除 / 重学

2.3 关键用户旅程

旅程 A：情境学习 + 收藏

1
首页 → 进入「具体情境」（咖啡馆/餐厅/图书馆）→ 打开 Lesson 页
2
点击句中单词 → 弹出 Ask Claw 解释（优先 AI，无 Key 时本地术语表兜底）
3
点击「收藏」→ 写入浏览器 localStorage
4
随时进入「我的收藏」→ 查看/筛选/删除，形成复盘闭环

旅程 B：Ask Claw 上下文问答

前端把 page_type / lesson_slug / selected_text / context 一并提交给 POST /api/ask-claw，后端注入 System Prompt（中文解释、英文桥接、不编造 lesson、不复制外源、输出上限 700 token），确保回答贴合当前页面语境且受控。

旅程 C：News 阅读

用户选分类（科技/美食/旅行/财经/体育…）→ 前端请求 /api/news?category= → 后端用 Google News RSS（西语）拉取并 15 分钟缓存 → 返回标题/来源/原文链接，用户点开即练阅读。

2.4 首页吉祥物引导流程（零灵灵）

首页以「零灵灵」2D 动画猫作为首次体验钩子，用一段 12 秒开场动画叙事，降低新用户认知负担：

左侧缓步走入（腿部循环 + 身体起伏 + 尾巴摆 + 眨眼） → 行至右端时发现正中央挣扎的小丑鱼（经典橙白黑配色） → 露出狡黠反应（眼睛瞪亮、微笑张嘴露两颗小虎牙） → 前爪捧起小丑鱼、左顾右盼 → 定格为端坐看向用户的静态猫。
同期标题区 「Spanish Claw」 的 C 字母循环四态切换（ñ 徽章书写 / 咖啡杯滑入 / 猫爪盖章 / 闪电突发），C 完成一次变换后右侧 「我帮你」 逐字浮现。

三、检验、检测报告与测试

质量保障是 PM 必须兜底的环节。本章为文档第三重点：从功能、交互、LLM 接口、跨浏览器/无障碍四个维度说明测试设计与结论。

3.1 测试策略

  • 功能测试：覆盖核心闭环（听→点→查→藏→复盘）与全部页面路由 / API 契约。
  • 交互/动画 QA：首页零灵灵 12 秒时间轴逐帧核验（走路→小丑鱼→反应→抱鱼→端坐）与 C 字母四态切换。
  • LLM 接口与降级测试：验证 5 种 Provider 的可用性探测、Key 缺失/超时时的自动降级到本地术语表。
  • 跨浏览器与无障碍：Chrome/Edge/Safari 一致性；prefers-reduced-motion 下关闭动画并直接呈现终态。

3.3 动画 / 交互 QA 要点

  • 零灵灵为内联 SVG + CSS 关键帧，零外部图片依赖，避免「静态卡片平移」观感；腿部循环、尾巴摆、眨眼、坏笑露虎牙均为真部件动画。
  • 小丑鱼复用经典橙/白/黑配色与扑腾摆动；出现位置与标题「Spanish Claw」居中对齐，叙事一致。
  • C 字母四态切换与「我帮你」浮现的时序经过校准：C 完成首次变换后延迟触发，避免抢戏。

3.4 LLM 接口与降级测试

这是本项目最关键的质量风险点。Provider 抽象层（BaseProvider + ProviderManager）把 5 种模型统一为 ask(question, context, system_prompt, model) 接口，并通过 is_provider_available + 300 秒健康度缓存决定可用性；当显式 Provider 不可用、或未配置 Key、或请求抛 ProviderUnavailableError 时，一律回退到 Local Glossary。测试覆盖：Key 缺失、模型 401/超时、显式指定不可用 Provider 三种降级路径，结论均为「核心学习路径不受影响」。

3.5 跨浏览器与无障碍

  • 前端为零构建依赖的原生 HTML/CSS/JS，兼容性由浏览器原生能力保证，无 Babel/PostCSS 风险。
  • 遵循 prefers-reduced-motion：用户开启「减少动态」时，动画整体关闭并直接呈现终态（端坐猫 + 标题），兼顾 vestibular 无障碍。
  • 吉祥物区带 aria-label 叙事描述，标题/按钮语义化，便于读屏。

3.6 测试结论

12 项用例全部通过。核心闭环、LLM 降级、首页动画、跨浏览器/无障碍均达到交付标准；遗留优化项见第五章反思（如补充 Playwright/pytest 自动化回归、增加移动端真机验收）。

四、技术栈

本章完整披露前后端与 LLM 接口，便于技术评委审阅架构与工程取舍。

4.1 前端

  • 渲染方式：Flask + Jinja2 服务端渲染（SSR），无前端框架、无打包构建（0 构建依赖）。
  • 结构：templates/ 共 9 个页面模板（index / lesson / saved / pronunciation / grammar / grammar_detail / vocabulary / news / buddy / about）；static/ 为原生资源。
  • 样式：style.css（原生 CSS，含设计变量 --warm-ink 等暖色调主题、响应式与动画关键帧）。
  • 脚本：home.js（首页故事动画 + C 字母四态 + 吉祥物引导）、app.js（通用）、audio.js（听力播放）、news.js、pronunciation.js。
  • 吉祥物：「零灵灵」为内联 SVG + CSS 关键帧的 2D 动画猫（腿循环/尾摆/眨眼/坏笑），非位图平移，体积仅数十 KB。

4.2 后端

  • 语言/框架：Python + Flask（Flask>=3.0,<4.0），应用入口 python -m app.app，默认 http://127.0.0.1:5000。
  • 路由层：app/routes.py 定义蓝图 main：页面路由（/ /lesson /saved /pronunciation /grammar /vocabulary /news /buddy /about）+ REST API（/api/lessons · /api/vocab · /api/news · /api/pronunciation-targets · /api/ai-providers · /api/ask-claw）。
  • 数据层：app/data_loader.py 从 data/*.json 读取（lessons / vocab / grammar / glossary / pronunciation_targets / local_rules / source_pool）。
  • 新闻模块：app/news_service.py 用标准库 urllib + xml.etree 直连 Google News RSS（西语），无任何第三方 SDK 依赖，15 分钟线程安全缓存。
  • 配置：app/config.py 经 python-dotenv 读环境变量。

4.3 LLM 接口抽象层（重点）

这是本项目的架构亮点：把多模型差异收敛为一个统一接口，并内建可用性探测 + 自动降级。

  • 抽象契约：app/ai/base_provider.py 定义 BaseProvider.ask(question, context, system_prompt, model)（抽象方法），所有 Provider 实现同一签名。
  • Provider 实现：OpenAI、Anthropic Claude、DeepSeek、Gemini 四类远程模型 + Local Glossary（本地术语表兜底）。
  • 管理器：app/ai/provider_manager.py 提供 get_available_providers / resolve_ask_provider / get_provider；check_provider_health 带 300 秒 TTL 缓存避免频繁探测。
  • 环境变量（config.py）：AI_PROVIDER（默认 local）、AI_MODEL（默认 gpt-5-mini）、OPENAI_MODEL、GEMINI_MODEL（gemini-2.5-flash-lite）、CLAUDE_MODEL（claude-sonnet-4-5）、DEEPSEEK_MODEL（deepseek-chat）。
  • 核心接口：POST /api/ask-claw 接收 question + 页面上下文，注入 Ask Claw System Prompt（中文解释、英文桥接、不编造 lesson、不复制外源、max_output_tokens=700），返回 {answer, provider, model, source}；source 区分 ai 与 local_glossary。
  • 降级保障：无 Key / 模型异常 / 显式 Provider 不可用 → 自动落到 Local Glossary，保证「查」这一闭环永不中断。

4.4 数据层

data/ 包含 lessons.json（情境听力材料）、vocab.json（词库）、grammar.json（语法模块）、glossary.json（本地术语表，兜底解释源）、pronunciation_targets.json（发音靶词）、local_rules.json、source_pool.json、sample_user_data.json。数据驱动设计，新增内容无需改代码。

五、项目反思（PM 方法论收获）

  • 需求分析：把「学西语好难」拆成四个可被产品解决的原子痛点，并用 MoSCoW 把 MVP 资源压在「闭环」而非「功能堆砌」，避免了初学者产品常见的贪多。
  • 业务流程设计：用「听→点→查→藏→复盘」一条主线串起所有页面，让每个模块都能回答「它服务于闭环的哪一步」，避免功能孤岛。
  • 检验与测试：把 LLM 不确定性当作一等公民——用 Provider 抽象 + 自动降级，把「模型可能挂」变成「用户无感」，这是 AI 产品上线前必须做的质量兜底。
  • 后续迭代：补自动化回归（Playwright/pytest）、真机移动端验收、用收藏数据做个性化推荐，以及把 Buddy 从「展示」升级为「基于学习行为的陪伴」。
